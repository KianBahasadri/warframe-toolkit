# Grakata

A browser app for tracking Warframe equipment using the fields from your spreadsheet, relic quantities, and searching the official drop tables. Built with React, TypeScript, and Vite. Browse and try the app without an account; sign in to save your inventory and views. Accounts use your Warframe username and a generated access key, with no password or email. A personal bookmark link can sign you in automatically. No paid service or API key is required. Catalog browsing and screenshot recognition work offline, and account saves work through the running local server without internet access. Drop-table updates need an internet connection; the most recent successful copy remains available through the local server while offline.

## Run

Requires Node.js 22.18+ and npm.

```sh
npm install
npm run dev
```

Open **http://127.0.0.1:5173**. Account data lives on this server. Sign in from another browser connected to the same server to use the same inventory. Older browser saves and display preferences still belong to their original hostname and port.

```sh
npm run build       # Production files in dist/
npm run preview     # Preview the production build on port 4173
npm test            # Accounts, catalog, drop-table parsing, filtering, OCR matching, storage and CSV tests
npm run test:browser
```

Browser tests use an installed Chromium at `/usr/bin/chromium`; set `CHROMIUM_PATH` for another location. Both `npm run dev` and `npm run preview` provide `/api/account/*`, `/api/droptables`, and the background drop-table updater. Browser tests use isolated account databases and never create accounts in your local database. The official website does not allow direct cross-origin browser requests, so the local server retrieves and parses its public HTML on a schedule. The endpoint only reads the resulting cache. Static hosting alone supports browsing and temporary edits. Saving requires the same-origin account endpoints from `server/accounts.ts`; Drop Tables also requires the endpoint and updater from `server/dropTableCache.ts`. OCR assets are copied locally during `npm install` and included in `dist/`; screenshots never leave the browser. HTTPS or localhost is required for browser APIs such as `crypto.randomUUID`.

To run the same browser checks in Firefox, install its Playwright build with `npx playwright install firefox`, then run `WARFRAME_TEST_BROWSER=firefox npm run test:browser`.

## Cloudflare hosting

The hosted deployment uses Cloudflare Workers Static Assets, **D1 for accounts and saved inventories**, and SQLite Durable Objects for request coordination and scheduled drop-table caching. Terraform manages the deployment, including code, assets, database migrations, routing, DNS, and the update schedule. See [deployment and recovery instructions](infra/cloudflare/README.md). `npm run build:cloudflare` builds both frontend and Worker; `npm run test:cloudflare` checks the Cloudflare runtime locally. Normal `npm run dev` continues to work without Cloudflare credentials.

Terraform state is stored in a private **R2** bucket managed by Terraform, with locking shared by local and automated deployments. The [production workflow](.github/workflows/deploy.yml) is active: it tests pushes to `main`, deploys with Terraform, and checks the live release. The `CLOUDFLARE_API_TOKEN` repository secret is configured, and the [first GitHub deployment passed](https://github.com/KianBahasadri/warframe-toolkit/actions/runs/38194984853). GitHub credentials stay on the host, outside `node-dev` and the shared checkout; see the [completed host-side handoff](infra/cloudflare/GITHUB-HANDOFF.md). The same Cloudflare token authenticates R2, without separate stored credentials. Local state is rejected by the automated deploy command.

## Inventory

New accounts start with an empty inventory, unless you choose to copy current data during signup. Existing local inventories are shown to guests without being overwritten. The older reference inventory transcribes **35 visible weapon rows** from the supplied image; it remains in `src/data/reference.ts` for regression tests and is not seeded into new accounts. That transcription is partial, includes only visible fields, and is not independently verified gameplay advice.

All 14 spreadsheet fields are stored: Owned, Weapon Name, Don't Keep, Crafting Ingredient, Crafting Target, Variant, Incarnon, Quest Weapon, Upgraded, Mastered, Meta / Powerful, Slot, Has Prime Variant, and Override. Rank, notes, source, and modification time are also retained. The same fields support Warframes, primary/secondary/melee weapons, Archguns, Archmelee, companion and exalted weapons, Kitguns, and Amps.

**Alt+1**, **Alt+2**, **Alt+3**, and **Alt+4** switch to Weapons, Warframes, Relics, and Drop Tables, matching the tab order. **Alt+N** opens the current collection's add form; **Alt+I** opens screenshot import. Shortcuts are paused while editing a field or using a dialog.

Weapons, Warframes, and Relics share the same toolbar and table layout: search, **Filters**, **Columns**, result counts, add, and export controls. Column menus, sorting priorities, active filters, and keyboard navigation work the same way in all three. The available fields, filter choices, and editing controls follow each collection's data; screenshot import remains available for equipment only.

- Ownership and mastery checkboxes update immediately and save automatically when signed in; they remain independent of rank. Select a name for **Weapon details** or **My inventory**.
- Signed-in users start with **Owned only** checked under **Filters** in Weapons and Warframes. Uncheck it to browse the entire catalog, including unowned equipment. Guests start with the entire catalog visible. Browsing never adds catalog entries to your save. Checking ownership or saving an inventory edit adds only that equipment.
- Search names, crafting targets, notes, weapon types, tags, and quest names. Open **Filters** to choose slot, Incarnon status, weapon type, variant, mastery, quest rewards, crafting use, Foundry recipes, Prime counterparts, vault status, recommended action, and maximum required MR. With the panel closed, only controls changed from their defaults remain visible. Returning a filter to its default hides it again; **Reset filters** restores the initial view for the current sign-in state.
- The default equipment table shows the name and image, ownership, current rank, mastery, Incarnon status, upgrades, recommended action, and crafting target. Incarnon distinguishes native forms from Genesis compatibility. **Columns** adds or removes individual columns, including all 14 spreadsheet fields and notes; the name stays visible. **Reset to default** restores the starting columns and their order. Column choices and order are remembered locally across Weapons and Warframes, with separate choices for Relics, independently of saved inventory. Slot appears under the name unless its own column is shown. Routine values and checkboxes use neutral colors.
- Drag a column header left or right to change its position. Its cells follow the pointer while neighboring columns slide aside to preview the new layout; the table scrolls horizontally when you drag near an edge. Release to apply the move, or press **Escape** to slide back to the original layout. Reduced-motion preferences disable the sliding transitions. The header menu also offers **Move left** and **Move right** for keyboard and touch use. Hidden columns retain their positions when shown again. On wider screens, the first column stays pinned as the table scrolls.
- Left-click or right-click a column header to open its menu for sorting, sort priorities, filters, and adding/removing columns. **Enter**, **Space**, and **Shift+F10** also open the menu while the header is focused. Choose **Sort ascending** or **Sort descending** in the menu; selecting the active direction again removes that column’s sort. Sort by any number of columns; numbered arrows show their priorities. Changing direction keeps a column's priority, and **Sort priority** moves it earlier or later. Unknown ranks sort last in either direction.
- Column filters support text matching, yes/no and category choices, and rank comparisons or unknown ranks. Active filters appear above the table and remain visible if their column is hidden; select one to edit it or use its **×** to remove it. Matching controls in **Filters** replace the corresponding column filter, and **Reset filters** clears both kinds.
- **Recommended action** is calculated from mastery, catalog facts, crafting progress, and personal planning fields. Hover over an action to see its reason in a tooltip; filters and sorting use the calculated action. See the priority rules below.
- Known equipment gets its slot, variant, crafting targets, Incarnon eligibility, quest rewards, and Prime counterpart automatically. Those facts are read-only. Keep preferences, ownership, mastery, rank, upgrades, favorites, and notes remain personal.
- Catalog suggestions can be replaced with a custom item name when adding equipment. Custom items retain manual fields and an initials placeholder when no game image is known.

### Recommended actions

Weapons and Warframes use the same ordered formula in `src/lib/recommendations.ts`. The first applicable rule wins:

1. **Master** owned, unmastered equipment before any crafting, upgrade, keep preference, or disposal. Unowned, unmastered equipment gets **Acquire & master**; unowned, mastered equipment gets **No action**. Current rank does not override the separate mastery fact, including after Forma and for rank-40 weapons. Exalted equipment gets **Use** or **No action**, since it has no separate mastery. Permanent quest rewards such as Excalibur Umbra and Skiajati get **Use** after mastery.
2. **Use for crafting** when an exact crafting target is neither owned nor mastered. Reasons list target names and the required copies of this ingredient; variants are never substituted. **Craft a spare** instead when the current copy has upgrades, an installed adapter, a favorite flag, or a quest use, or when a variant, Incarnon candidate, or Keep override merits preserving it and there is no Prime counterpart. This does not claim that all other recipe resources are available. Completed targets are ignored; rebuilding them or stocking duplicate copies is not modeled.
3. A **Prime counterpart always excludes Keep**, even with a Keep override, upgrades, or favorite flag. After mastery and crafting uses, suggest **Sell**, **Remove Incarnon** first for a recorded installed adapter, or a Helminth action for a base Warframe. Quest disposal gets **Review** for its use, replacement, and sale restrictions. This is the chosen collection policy, not a claim that Prime is always the strongest build or currently obtainable.
4. Without a Prime counterpart, the manual Keep override wins over Don't keep. Disposal preferences still come after mastery and crafting uses, and use the same adapter, Helminth, and quest checks.
5. **Add Incarnon** for Genesis-compatible equipment without a recorded installed adapter; **Keep** installed Genesis and native Incarnon equipment. Unknown installation state gives conditional advice. The existing Incarnon field means eligibility, and Upgraded does not imply an installed adapter.
6. **Keep** favorites, upgraded equipment, quest rewards, special variants, and Warframes without a Prime counterpart. Otherwise suggest **Sell** for catalog equipment or **Review** for unknown custom equipment.

**My inventory** includes **Incarnon adapter installed** for Genesis-compatible equipment and **Helminth ability unlocked** for base Warframes, each with Unknown/Yes/No. Before base-Warframe disposal, unknown Helminth status gets **Check Helminth**, No gets **Subsume**, and Yes allows the later disposal recommendation. Prime and Umbra variants are never recommended for subsuming. Missing fields in older saves remain unknown. Screenshot imports preserve both fields; computed recommendations are never saved into personal records, and browsing never changes inventory.

Game-mechanic references: [Genesis installation and variant compatibility](https://www.warframe.com/en/patch-notes/pc/33-0-0), [adapter removal at Cavalero](https://www.warframe.com/en/patch-notes/pc/33-5-0), [Helminth subsuming](https://www.warframe.com/en/patch-notes/pc/29-0-0), and [permanent quest rewards](https://support.warframe.com/hc/en-us/articles/9503863772557-Quest-Tips-Post-Second-Dream-Spoilers-Warning). The formula uses the bundled catalog and entered facts, not live build rankings, spare-copy counts, resource balances, or unlock progress. Recommendations do not perform any in-game action.

## Weapon database

The bundled snapshot contains **683 weapons** and **122 Warframe-category entries**, with **789 distinct local game images** shared by 805 entries. It includes weapon variants, Archguns/Archmelee, companion weapons, exalted weapons, seven modular Amp prisms plus Mote Amp and Sirocco, six Kitgun chambers, and Zaw strikes. Modular families represent their mastery-bearing part; arbitrary assembled combinations and custom names are not separate catalog entries.

Each weapon's details include its image and description, MR, unmodded stats and attack modes where exported, damage types, polarities, maximum rank, recipes, credit costs, materials and quantities, build times, and weapons that consume it. Expand a crafted material or weapon to inspect its component recipe. Recipe costs are per listed batch and do not include blueprint purchases or the cost of obtaining drops; ingredient recipes show their own costs. Identical required weapons are combined (for example, Aklex Prime consumes two Lex Primes), and base/Prime variants are not interchangeable.

Incarnon data distinguishes native transformations from Genesis compatibility and includes adapter installation materials and available attack-mode stats. Eligibility does **not** mean an adapter is installed. Evolution challenges and perk choices link to the corresponding wiki page. Quest data identifies weapon rewards separately from blueprint rewards. Acquisition includes exported drops, blueprint prices, market prices, and faction/vendor tags where available; it is not a complete live vendor inventory or event schedule.

Sources are [WFCD/warframe-items](https://github.com/WFCD/warframe-items) and the community-maintained [Warframe Public Export Plus](https://github.com/calamity-inc/warframe-public-export-plus), supplemented by sourced quest rewards in `scripts/catalog-supplements.mjs`. Every snapshot records pinned upstream revisions and its retrieval date. Images are served locally; attribution and download provenance are in [public/images/SOURCES.md](public/images/SOURCES.md). Browsing and filtering make no external requests. Wiki/source links open only when selected.

Run `npm run catalog:update` to regenerate the snapshot and images. It validates ingredient names and downloads all new or changed images before replacing the catalog; it never touches browser saves. Tests cover local image integrity, exact variant matching, recipes, Incarnon eligibility, quest rewards, filtering, and preservation of saved fields. Sources can lag game updates or omit details: absent recipes and drop locations are labeled as unrecorded, not free or unobtainable. Modular assembly stats depend on the chosen parts, and the assembled Mote Amp's stats are unavailable in these sources.

Existing saves retain all 14 original fields and historical planning values in the account profile, including when copied from browser storage. The UI and CSV exports overlay current catalog facts without rewriting those historical values in the saved JSON. New saved entries receive current catalog facts. Database updates never change ownership, mastery, current rank, keep decisions, upgrades, or notes.

## Relics

The **Relics** tab tracks each name and refinement as a separate stack, with a quantity and notes. It starts empty. Add names using the bundled catalog suggestions or enter an era and code manually. Use the quantity buttons for immediate changes, or select a name to edit or remove its stack. A quantity of zero keeps the entry and notes; **Owned only** hides zero quantities.

Search names and notes, then open **Filters** for era, refinement, or **Owned only**. Changed filters remain visible when the panel closes. The toolbar shows matching stacks and the total relic quantity. **Columns** controls the name, era, refinement, quantity, and notes columns. Drag headers or use **Move left** and **Move right** in their menus to reorder columns. Column menus provide sorting priorities, text and choice filters, and numeric quantity comparisons; hiding a filtered column keeps its filter active. **Reset filters** clears search and both kinds of filters. **Export CSV** on this tab exports the relic collection. The catalog contains 798 names from [WFCD/warframe-items](https://github.com/WFCD/warframe-items), refreshed with `npm run catalog:relics`. Relics are currently entered manually; screenshot import handles equipment only.

## Screenshot import

1. Open **Import screenshots**. **Inventory** and **Codex** have separate sections, supplied game examples, and **Instructions** buttons. Inventory shows equipment ownership and current ranks; Codex shows collection mastery. Select either example or its upload prompt to choose files. Both guides also link to their example at full size.
2. Drop or browse for English PNG, JPG, or WebP screenshots in the appropriate section, each below 20 MB and 32 megapixels. Before adding images, move the mouse over the left or right side of the page to highlight **Inventory** or **Codex**, then paste into the highlighted side. The highlight fills that side and partially slides the other side away, shrinking its example image and hiding the text beneath it. Moving to the other side restores its image and text. The first image finishes the slide, hides the other section, and expands the selected section to the full width. On narrow screens the sections stack and the highlight follows the pointer vertically. Keyboard focus on either upload area also selects it; Inventory is selected initially. Reduced-motion preferences disable these animations. Use **Add screenshots** to keep choosing, dropping, or pasting images into that batch, up to 10 images total. Images added while recognition is running are queued.
3. Text recognition runs in the background. The review list stays visible and editable, and new matches appear as each image finishes. Review matched names, ownership, mastery, and rank; finish or cancel reading before importing.
4. Correct a matched name with its dropdown, deselect unwanted results, and import the selected rows. The screenshot gallery stays visible and shows every image in the batch, including images still being read. Select a thumbnail to open the **Screenshot gallery** modal. Flip through all images using its previous/next buttons or the left/right arrow keys; Home and End jump to the first and last images. Escape or the close button returns to the review list.

Adding images preserves earlier matches, name corrections, ranks, and checkbox choices. Canceling recognition keeps completed matches and discards unread images so you can add them again. **Clear** restores both source choices. Importing selected rows takes you directly to **Weapons**; open **Import screenshots** again to start a fresh batch. Help dialogs never import their example image or change the source of an active batch. The examples are bundled in `public/images/import/`; provenance is recorded alongside them in `SOURCES.md`.

The reader uses [Tesseract.js](https://github.com/naptha/tesseract.js) entirely in the browser with a bundled English model. It matches names against the 805 bundled equipment names in the weapon database. `npm run catalog:update` refreshes that snapshot and its licenses; it never modifies your saved inventory.

Recognition is a starting point for review. Browser tests cover both supplied 1920 × 1200 Inventory/Sell screenshots: all 37 readable names, exact variants, and ranks (36 at rank 30, Vasto at rank 0). The supplied Codex screenshot is also tested against all 32 names and mastery laurels, including Braton and Braton Prime as separate entries. Tests cover a resized, offset Codex image with obscured and false badges, synthetic text, repeated images, review edits, and saving without losing planning fields or prior mastery. The original images and manually checked expectations are documented in `tests/fixtures/README.md`. Other game themes, UI scales, layouts, and actual lower-resolution captures still need testing. The reader does not identify equipment from its picture or recognize arbitrary custom names. Prime and other variants are matched separately. Blueprint/component lines are excluded; uncertain fuzzy matches are not selected automatically.

Inventory matches initially count as owned; Codex matches start with ownership unchecked. Codex card grids establish neither current rank nor ownership, so their ranks remain blank and existing saved ranks and ownership are preserved. The Codex reader locates aligned pale name strips and reads them apart from the artwork. It checks for the mint laurel's shape in each card's upper-right corner, relative to that card's size. A full progress bar or green patch alone does not establish mastery. This badge detector is limited to the supplied light-label/mint-badge appearance; other themes and uncertain or cut-off badges require manual review. Images without a recognized card layout fall back to text recognition, without badge inference.

Rank labels such as `[30]`, `[0]`, `RANK 30`, and `UNRANKED` are read alongside a single matched item. A wrapped Inventory rank must sit directly below one uniquely aligned name; bare digits also require neighboring bracketed card labels in the same row. Ambiguous associations are left blank. Two grayscale contrast passes improve generic text recognition over textured backgrounds without fixed card coordinates.

Reaching the catalog's maximum rank checks **Mastered**: normally 30, or 40 for weapons such as Paracesis, Kuva, Tenet, and Coda weapons. Modular equipment and Amps need separate mastery evidence because a rank label does not establish gilding; non-masterable entries are not marked mastered from rank or badges. Explicit same-line “Mastered” text and recognized Codex laurels also establish mastery. “MAX” or an unidentified icon alone is insufficient. Correcting a name recalculates automatic mastery unless you have set the checkbox yourself; changing rank retains mastery established by a Codex badge or explicit text. No absence, missing badge, or lower rank in a screenshot clears prior ownership or mastery.

Repeated names merge into existing entries. Imports preserve keep preferences, crafting notes, Incarnon flags, upgrade status, and all other planning fields. A new observed rank may decrease after Forma. Screenshot files are kept only in the current import view, not in persistent storage. Import history stores filenames and counts.

## Live drop tables

**Drop Tables** uses a local copy of [Warframe's official PC drop tables](https://warframe.com/droptables), updated automatically **every hour while the server is running**. Opening or reloading the page does not trigger an upstream fetch, and there is no Refresh button or refresh shortcut. The **info button beside the title** opens a browsing guide with the official source, publisher's update date, and **Last fetched** date and time, including the browser's local timezone. Last fetched records the last successful upstream retrieval. Failed updates keep the previous data and timestamp, show an error, and retry automatically after five minutes.

The server saves successful data atomically to `.cache/drop-tables.json`, which is excluded from Git. On startup it immediately serves a valid saved copy and schedules the next update using its fetch time; a missing or overdue copy starts a background update independently of page requests. Malformed cache files are preserved under an `.invalid-*` name before recovery. No drop-rate snapshot is bundled with the app, and no external proxy service is used. The updater follows only the official redirect chain, imposes a timeout and download limit, and parses text without executing upstream HTML. Closing the server cancels its updater.

The browser reads the server's cached copy initially and checks for changes once a minute while the Drop Tables tab is open. Conditional requests avoid transferring unchanged data; returning to the tab resumes the existing read schedule. During first-run cache preparation it checks every five seconds until data is available. These checks never fetch from Warframe. Background updates preserve the current view and any open odds calculator. Other app features remain usable if the endpoint is offline.

- Start with **Mission type**, **Item**, **Location**, **Relic**, **Bounty**, or **Enemy / source**. Choose a result to see its individual drops, then use the back button or browse choices to switch groups. Mission types group mission rewards; locations include missions and bounties with a published location. Item and source views include all categories. Relics group their refinements under one name, while each refinement, rotation, stage, and repeated reward keeps its own entry and chance.
- Search across rewards, sources, locations, rotations, and other text fields in the current browse view or group. Quoted phrases, exclusions, and field queries combine: `"nova prime" -refinement:intact chance:>=10`, `mission:survival rotation:c`, or `source:"heavy gunner" within:>30`. **Search help** lists all fields and numeric operators. Switching browse choices retains the search and filters.
- **Filters** offers searchable multiple selections for category, location, mission type, rotation, stage, relic era, refinement, and rarity, plus drop-chance ranges. Different fields combine with AND; selected values within a field combine with OR. Active filter chips remain visible when the panel closes.
- Groups show counts and short previews; items show the highest individual published chance among their matching entries. **Sort by** switches between name order and drop chance in either direction. Group chance ordering compares each group’s highest known chance, with unknown odds last; rates are never added together. Individual drops emphasize the drop chance and show rotation, stage, refinement, and rarity where available.
- Results use locally bundled game artwork for rewards, enemies, relics, and mission environments. Item groups show the reward; browsing an item's sources shows the enemy, relic, or mission. Blueprints depict the exact recipe result, relics share their era's render, and some components share the game's generic component art. Environment images represent the named location or mission, not a screenshot of every node. The image label identifies what is pictured. Unknown names and failed images show **Artwork unavailable**; no base or alternate equipment variant is substituted. Reward frame colours follow the publisher's within-table rarity, not the overall drop chance.
- **Saved views** stores the browse mode, selected group, query, filters, and sorting in the signed-in account. Guests can load existing local views and share links, but must sign in to save a view. Existing table-era views and links still open their filters in the item browser, and their stored settings are retained. Old page-size settings are accepted but no longer limit the results. Unreadable saved views are preserved. **Copy view link** shares the current settings in the URL and uses the latest automatic update when opened; it includes no inventory or drop-table rows.
- Results form one scrolling list without pagination. Smaller lists appear in full; large lists add more results automatically near the bottom, using the data already loaded. Search and sorting always cover the complete dataset. Images load only as needed, and background updates preserve how much of the list is shown.
- Open a reward for the published rates, an independent-attempt odds calculator, source links, and buttons to browse the same reward or source. Up/Down and Home/End move between results; **End** makes the final result reachable even in a large list, and Enter/Space opens details. **Export CSV** (**Alt+E**) exports every matching entry in the current group or browse view with all fields, including results not yet shown. Percentages are raw numbers and unknown rates are empty.

The parser preserves mission rotations, bounty stages, relic refinements, and enemy/container table roll rates. Enemy reverse indexes repeat source indexes and are excluded when the corresponding source index exists; identical entries within a table remain separate. Drop chance is the within-table percentage multiplied by the source table's roll rate when separately specified. Rates above 100% indicate multiple rolls; their overall chance and calculator are left unavailable rather than assuming independence or a roll count. Unknown chances sort last in either direction. The official rarity label refers to the within-table rate.

Published PC tables may omit rewards or lag hotfixes, and a listed relic or source may be vaulted or inaccessible. Automatic updates retrieve the published document, not the game's current bounty/event rotation. The calculator assumes independent opportunities at the displayed source, rotation, and stage, with no squad, booster, or pity modifiers. Repeated entries are not automatically combined.

The full live page was tested during implementation on 2026-10-11: 43,367 source-index entries across 17 categories, no skipped reward rows, and 10,005 repeated reverse-index rows excluded. Counts will change with the upstream page. Automated tests use a small synthetic HTML fixture and mocked HTTP responses; no official drop-rate dataset is checked into the repository.

`npm run catalog:drop-art` regenerates `src/data/drop-art.json` and the local artwork from the equipment catalog's pinned WFCD/game-export revisions, the live reward names, and curated game scenes in `scripts/drop-art-scenes.mjs`. It keeps artwork separate from live rates, validates image signatures, reuses local equipment images, and records original URLs and SHA-256 fingerprints in `public/images/drops/sources.json`. Browsing only loads local images as needed, with no external image requests. Artwork coverage is partial and does not determine whether a reward is available. See [artwork attribution](public/images/drops/SOURCES.md).

## Accounts, storage, and exports

Use your **Warframe username** to create an account. The server generates a random **access key** and shows it once, together with a personal sign-in link. Copy the key, download the text file (which includes the link), or save the link as a browser bookmark. Confirm that you saved one before closing. Anyone with the key or link can access your account; keep it private. There is no email recovery. Usernames are compared without case sensitivity and keep their entered capitalization. Accounts are independent of Warframe; this does not verify ownership of a game account or connect to Digital Extremes.

Sign in with your username and key, or open your saved bookmark. Sign-in links use `#sign-in?username=…&key=…`; the credentials stay in the URL fragment, so they are not sent as request URLs or referrers. The app immediately removes them from the address bar and that history entry, then sends the key in a same-origin POST to sign in. The saved bookmark remains reusable. Normal navigation and shared drop-table links do not contain credentials. No key is saved in localStorage or sessionStorage.

While signed in, **Account → Replace access key** generates a new key and link. This invalidates the old key, old bookmarks, and other sessions, while preserving the current session and all saved data. If a signup response is interrupted, reopen the app and replace the key from the signed-in account. If you lose both the key and link and have no active session, you cannot recover access.

Guests can browse every section, use screenshot recognition, export CSV, and make temporary edits. Guest inventory changes are held in memory and disappear on reload. Signing in is required to persist equipment, relics, import history, and drop-table views. Signup offers **Save my current inventory and views to this account** when valid data exists; signing in to an existing account loads that account's data without merging the guest inventory. Signing out returns to the guest workspace from before sign-in.

Accounts and their versioned profiles are stored in `.data/accounts.sqlite`, excluded from Git and blocked from Vite file serving. Keep this file private; back it up with the server stopped so SQLite has closed its journal. `ACCOUNTS_DATABASE` can set another private database path (outside public/static directories). A public installation needs HTTPS; set `ACCOUNTS_ORIGIN` to its exact HTTPS origin when using a reverse proxy so origin checks and Secure cookies match that address. Development and preview share the default database when run from this checkout.

Access keys have 32 cryptographically random bytes (256 bits), encoded as `wft_` plus 43 base64url characters. Only SHA-256 digests are stored; generated keys do not need expensive password stretching. New accounts cannot choose their own key or password. Sessions use separate random tokens in HttpOnly, SameSite cookies, with only token digests stored in SQLite, following [OWASP's session guidance](https://cheatsheetseries.owasp.org/cheatsheets/Session_Management_Cheat_Sheet.html). Sessions expire after 30 days. Login attempts are throttled; writes require the app's origin, the current account ID, and the expected save revision. Account responses use `Cache-Control: no-store`. Account storage uses Node's built-in SQLite and crypto modules, without an external account provider.

Personal data is no longer written to browser storage. Older `warframe-toolkit.inventory.v1` and `warframe-toolkit.drop-views.v1` values are read for migration and preserved unchanged. Older inventory JSON without relic data loads with an empty relic collection and preserves all equipment fields. Theme and table-column preferences remain local display settings.

**Export CSV** on Weapons or Warframes exports the original equipment spreadsheet columns plus rank, notes, Incarnon installation, and Helminth ability status; the same action on Relics exports the relic collection. User text is escaped and formula-like values are neutralized for spreadsheet use.

While signed in, the save status distinguishes saved data and pending changes. Guests see a prominent **Sign in** button beside **Create account** in the header. Each opens its respective form directly. Failed saves keep the draft visible and offer retry, download, or explicitly discarding changes to reload the saved version. Signing out waits for a successful save. Conflicting edits from another tab or device are rejected instead of overwriting them. Unreadable local or server data is preserved instead of silently resetting it; the local error panel can download the original inventory for recovery.

## Code map

- `src/App.tsx`: navigation, account status, and inventory operations.
- `server/accounts.ts`: SQLite accounts, generated access keys, sessions, protected profile endpoints, and conflict detection.
- `cloudflare/`: hosted D1 account API, chunked profile schema, scheduled durable drop cache, and Worker entry point; shares validation and parsing with local development.
- `infra/cloudflare/`: pinned Terraform deployment, provider lock, and deployment/recovery documentation. `scripts/terraform.mjs` loads private credentials and invokes Terraform; `scripts/cloudflare-migrate.mjs` applies its D1 migrations.
- `tests/cloudflare/`: isolated Cloudflare runtime regression tests. `WARFRAME_TEST_BACKEND=cloudflare` also runs the existing browser suite against D1.
- `src/lib/account.ts` and `src/lib/useAccount.ts`: profile validation, legacy save loading, guest workspace, authentication, and serialized autosaving.
- `src/components/AccountDialog.tsx`: signup, access-key and bookmark saving, sign-in, key replacement, migration choice, and sign-out.
- `tests/browser/accountFixture.ts`: isolated real account API used by browser regression tests.
- `src/components/CollectionTable.tsx`: shared collection toolbar, filter panel, table, column preferences, row navigation, and add/export actions. Definitions supply columns, data access, filters, and cell rendering.
- `src/components/InventoryTable.tsx` and `src/components/Relics.tsx`: equipment and relic definitions and editing controls for the shared collection table.
- `src/components/`: also equipment details and editor, import review, and command palette.
- `src/components/useColumnDrag.ts`: shared pointer dragging, cancellation, and horizontal edge scrolling. Dragging updates the preview without rendering the collection; only release commits the column order.
- `src/components/columnDragPreview.ts` and `src/lib/columnDrag.ts`: inert previews of visible rows, column sliding, and stable insertion positions for columns of different widths.
- `src/components/ColumnPicker.tsx`, `src/lib/inventoryColumns.ts`, and `src/lib/relicColumns.ts`: column definitions, default layouts, and separate display preference namespaces.
- `src/components/ColumnMenu.tsx`, `src/components/TablePopover.tsx`, and `src/lib/tableView.ts`: shared column actions, bounded keyboard-accessible popovers, data-driven filter matching, and sorting priorities.
- `src/components/Select.tsx`: shared custom dropdowns with keyboard navigation, type-to-select, and viewport positioning; no native select popup or experimental picker CSS.
- `src/components/DropTables.tsx`, `DropBrowser.tsx`, `DropTableControls.tsx`, and `DropDetails.tsx`: live drop browsing, mode choices, group/reward cards, filters, saved/shared views, and odds calculator.
- `src/components/DropInfo.tsx`: drop-table guide and source details, including the last successful fetch time and timezone.
- `src/components/DropResults.tsx`: complete small lists, automatic scroll loading for large lists, and keyboard navigation across all results.
- `src/lib/dropExplorer.ts`: grouping and counts for the six browse modes, without merging entries or combining rates.
- `src/lib/dropArtwork.ts` and `src/components/DropArtwork.tsx`: exact artwork lookup by browse context, published rarity colours, and missing-image handling.
- `src/lib/dropTables.ts`: drop schema, query grammar, filtering, sorting, view validation, odds calculations, and CSV export.
- `src/lib/dropTableParser.ts`: streaming HTML parser for official reward hierarchies and conditional rates; used only on the server and in tests.
- `server/dropTables.ts`: fixed-source upstream fetch with bounded downloads and official redirects.
- `server/dropTableCache.ts` and `vite.config.ts`: hourly background updater, persistent cache, automatic retry, and cached endpoint shared by development and production preview.
- `src/lib/useDropData.ts`: periodic conditional reads of the local cache, retained session data, and update errors.
- `src/components/ScreenshotHelp.tsx`: source-specific screenshot instructions and local Inventory/Codex examples.
- `src/components/ScreenshotGallery.tsx`: screenshot modal with previous/next controls and keyboard navigation.
- `src/lib/weaponCatalog.ts`: catalog/inventory projection, combined filters, and safe catalog-entry ownership updates.
- `src/lib/recommendations.ts`: shared equipment action priorities and reasons, using exact crafting targets and personal mastery/upgrade facts.
- `src/assets/warframe/`: bundled in-game tab icons; original asset links and attribution are in [SOURCES.md](src/assets/warframe/SOURCES.md).
- `src/lib/model.ts`: equipment schema and conservative import merging.
- `src/lib/relics.ts`: relic schema, name normalization, and validation.
- `src/lib/matching.ts`: full-label exact/fuzzy matching, rank association, and reviewable mastery observations.
- `src/lib/ocr.ts`: local OCR worker lifecycle and image preparation.
- `src/lib/codex.ts`: Codex name-strip location and conservative mastery-laurel matching, using the source-documented mask in `src/data/codex-mastery-mask.json`.
- `src/lib/storage.ts`: saved inventory validation and spreadsheet export.
- `src/data/reference.ts`: manually transcribed reference rows.
- `src/data/catalog.json`: generated equipment catalog; attribution in `CATALOG-LICENSE.txt`.
- `src/data/relics.json`: generated relic name catalog, using the same attribution.
- `scripts/build-catalog.mjs`: source normalization, recipes and reverse crafting dependencies, variant families, Incarnon and quest mapping.
- `scripts/update-catalog.mjs`: pinned source downloads and local image refresh; `catalog-supplements.mjs` holds sourced script-granted quest rewards.
