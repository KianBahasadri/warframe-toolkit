# Warframe Toolkit

Read `README.md` for setup, data semantics, and the code map.

- Save completed work and useful checkpoints in local Git commits regularly, without waiting for the user to ask.
- Keep the UI limited to useful controls and data. Do not add slogans, promotional headings, or decorative explanatory copy.
- Use player-facing terms such as rewards, sources, results, and equipment in UI copy and explanations to users. Do not call interface elements "cards" in user-facing text.
- Keep the app usable locally without an API key or uploading screenshots.
- Browsing and temporary edits are available to guests; saving personal data requires an account. Use the Warframe username and a server-generated access key, with no chosen password or email. Personal sign-in bookmarks carry the key only in the URL fragment; consume and remove it promptly, and never add keys to shared view links or browser storage. Preserve older local saves for explicit migration, and never merge one account's data into another.
- Preserve the 14 original spreadsheet fields. Ownership, mastery, and current rank are separate facts.
- OCR is uncertain: keep a review step, never substitute base equipment for a variant, and never infer that missing equipment has been sold.
- Screenshot merges preserve existing planning fields and notes. Do not silently reset malformed saved data.
- `src/data/catalog.json` is generated by `npm run catalog:update`, and `src/data/relics.json` by `npm run catalog:relics`; the reference screenshot data is manually transcribed in `src/data/reference.ts`.
- Run `npm test` and `npm run build` after logic changes. Use `npm run test:browser` for changes to import, persistence, or interactive behavior. Browser tests use system Chromium or `CHROMIUM_PATH`.
- Keep the README's recognition limits accurate until real game screenshots have been tested.

## Development environment

- Future sessions may already be inside the Incus dev box (`node-dev`), as user `dev` in `/home/dev/warframe-toolkit`. Check `hostname`, `id`, and `pwd` before assuming host paths or entering the box again.
- The dev box provides isolation to protect the host from untrusted npm packages, install scripts, and other development tools. Run dependency installs, tests, builds, and development servers inside it as `dev`. If access fails, report the problem instead of silently running these commands on the host or weakening the isolation.
- From the host checkout, use the `dev` shortcut to enter and verify the project directory is available. Configuration and access documentation live in `~/dev-box` on the host.
- Once mounted, `/home/kian/warframe-toolkit` on the host and `/home/dev/warframe-toolkit` in the box share the same writable files. The box protects the host environment; changes to the shared checkout still affect the host copy.
